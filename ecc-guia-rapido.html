ECC — Guia de referência rápida

Instalação, componentes, comandos e formas de aplicação do Agent Harness Performance Optimization System para Claude Code, Codex, OpenCode, Cursor e outros agentes.

Repositório github.com/affaan-m/ECC

O ECC adiciona ao agente de código fluxos reutilizáveis de engenharia: planejamento, TDD, revisão de código, correção de builds, segurança, memória, hooks e pesquisa.

2. Pré-requisitos

Para o caminho recomendado, verifique se possui:

  • Node.js 18 ou superior
  • Git
  • Claude Code 2.1 ou superior no PATH, se for usar o plugin nativo
node --version
git --version
claude --version

3. Instalação recomendada

Claude Code — instalador universal

Não clone o repositório para este método. Execute:

npx ecc-universal@2.2.3 setup

Alternativas:

pnpm dlx ecc-universal@2.2.3 setup
yarn dlx ecc-universal@2.2.3 setup
bunx ecc-universal@2.2.3 setup

Para uma instalação pessoal típica, escolha Global user, Standard hooks e confirme. Abra uma nova sessão do Claude Code e valide:

/plugin list

O plugin deve aparecer como ecc@ecc habilitado.

Claude Code — plugin nativo

Dentro do Claude Code, execute:

/plugin marketplace add https://github.com/affaan-m/ECC
/plugin install ecc@ecc
Escolha apenas um método: instalador npx ou comandos nativos /plugin. Não use os dois, para evitar duplicação de skills, comandos e hooks.

4. Instalar em vários agentes

Para configurar Claude Code, Codex e/ou Kimi Code em um fluxo único:

npx ecc-universal@2.2.3 install --guided

Para automação, especifique tudo explicitamente:

npx ecc-universal@2.2.3 install --guided \
  --harness claude --harness codex --harness kimi \
  --claude-scope local --claude-hooks standard \
  --profile core --yes

Para apenas inspecionar o plano, sem gravar arquivos:

npx ecc-universal@2.2.3 install --guided --harness codex --dry-run
npx ecc-universal@2.2.3 install --profile core --target kimi --dry-run

6. Regras opcionais

Plugins do Claude Code não distribuem rules. Para adicionar padrões de código, copie apenas os pacotes relevantes:

git clone https://github.com/affaan-m/ECC.git
cd ECC
mkdir -p ~/.claude/rules/ecc
cp -R rules/common ~/.claude/rules/ecc/
cp -R rules/typescript ~/.claude/rules/ecc/

Troque typescript pela sua stack, como golang ou python. Comece com rules/common e apenas um pacote de linguagem/framework, porque regras são contexto sempre carregado.

Escopo por projeto

cd seu-projeto
mkdir -p .claude/rules/ecc
cp -R /caminho/para/ECC/rules/common .claude/rules/ecc/
cp -R /caminho/para/ECC/rules/typescript .claude/rules/ecc/

Copie o diretório inteiro da regra, não arquivos soltos, para preservar referências relativas.

7. Como aplicar no dia a dia

Planejar antes de codar

/ecc:plan "Adicionar autenticação OAuth"

Use para transformar um pedido em plano técnico, riscos, decisões e tarefas acionáveis.

Implementar com TDD

tdd-workflow

Use quando a mudança tiver comportamento verificável: escreva o teste que falha, implemente o mínimo e refatore.

Revisar alterações

/code-review

Use antes de abrir PR ou após implementar uma feature, para revisar qualidade, riscos e consistência.

Corrigir build quebrado

/build-fix

Use quando testes, lint, type-check ou build falharem e você precisar de um caminho estruturado de diagnóstico.

Refatorar e limpar

/refactor-clean

Use para reduzir duplicação, remover código morto e melhorar organização sem alterar comportamento.

Auditar segurança

/security-scan
agentshield scan --path .

Use antes de publicar mudanças sensíveis, integrar dependências ou revisar configurações de agente.

Analisar uma issue

/ecc:issue-review <número>

Use para investigar contexto, causas prováveis, impacto e plano de correção de uma issue do GitHub.

Preservar contexto

/save-session
/resume-session
/context-budget

Use ao pausar um trabalho longo, retomar no dia seguinte ou monitorar o consumo de contexto.

8. Fluxo de trabalho sugerido

Para uma nova funcionalidade, uma sequência simples e eficaz é:

/ecc:plan "Adicionar autenticação com OAuth"
tdd-workflow
/code-review
/security-scan

Para uma correção de bug:

/ecc:issue-review 123
/build-fix
/code-review

Para uma refatoração:

/refactor-clean
/code-review
/security-scan

9. Manutenção e diagnóstico

Para uma instalação feita pelo pacote universal:

npx ecc-universal@2.2.3 list-installed
npx ecc-universal@2.2.3 doctor
npx ecc-universal@2.2.3 repair
npx ecc-universal@2.2.3 uninstall --dry-run
npx ecc-universal@2.2.3 uninstall

Em um checkout do código-fonte:

node scripts/ecc.js list-installed
node scripts/ecc.js doctor
node scripts/ecc.js repair
node scripts/ecc.js uninstall --dry-run

10. Cuidados importantes

  • Segurança Instale apenas pelos canais oficiais: repositório affaan-m/ECC, pacotes npm ecc-universal e ecc-agentshield, GitHub App, plugin ecc@ecc e site ecc.tools.
  • Evite duplicação Não use simultaneamente o instalador universal e os comandos nativos /plugin.
  • Hooks Não copie manualmente hooks/hooks.json para ~/.claude/settings.json; o instalador reescreve os caminhos corretamente.
  • Comandos extras Os comandos /multi-* exigem o runtime separado ccg-workflow.
  • Codex /astra-review envia o diff para o Codex CLI/OpenAI e requer login prévio com codex login.
  • Versão O npx fixa a versão 2.2.3, mas isso não substitui revisar a origem e a integridade do pacote antes de executá-lo.
Guia de referência rápida baseado no README do repositório affaan-m/ECC. Revise sempre a documentação oficial antes de executar comandos que alterem arquivos ou configurações do seu ambiente.
