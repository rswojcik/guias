Guia Passo a Passo — Docker Compose no Ubuntu Server 26.04

Objetivo: instalar o Docker, aprender os comandos básicos do Docker e do Docker Compose, rodar o n8n com PostgreSQL e monitorar tudo com ferramentas leves

Ambiente de referência: uma VM com Ubuntu Server 26.04 LTS (instalação nova), Docker Engine do repositório oficial da Docker, plugin Docker Compose v2, n8n, PostgreSQL 18 e Dozzle

1. Como usar este guia e o que será montado

Execute as etapas na ordem. Cada etapa explica o objetivo, apresenta os comandos, diz o que você deve ver e termina com uma validação. Marque a caixa da etapa somente depois de confirmar o resultado.

Todos os comandos são executados no terminal da VM (via SSH ou console do hipervisor). Substitua os valores entre sinais de maior/menor, como <IP_DA_VM>, antes de executar. Não cole os sinais de maior/menor literalmente.

3. Conceitos essenciais em 5 minutos

Docker empacota uma aplicação com tudo o que ela precisa para rodar. Em vez de instalar PostgreSQL e n8n direto no Ubuntu, você “liga” pacotes prontos e isolados. Cinco palavras explicam quase tudo:

TermoO que éAnalogia
ImagemPacote pronto e somente leitura de uma aplicação (por exemplo, postgres:18). Fica guardada no servidor depois de baixada.A receita e os ingredientes embalados.
ContainerUma imagem em execução. Pode ser parado, apagado e criado de novo em segundos.O prato pronto, servido a partir da receita.
VolumePasta gerenciada pelo Docker onde ficam os dados que precisam sobreviver. Apagar o container não apaga o volume.A geladeira que fica, mesmo trocando o prato.
RedeRede virtual privada entre os containers. Dentro dela, um container encontra o outro pelo nome do serviço (o n8n fala com postgres).O ramal interno de uma empresa.
ComposeUm arquivo compose.yml que descreve vários containers, volumes e redes juntos. Um comando sobe ou derruba tudo.O cardápio completo do pedido.
Regra de ouro: containers são descartáveis; volumes não. Tudo o que não está num volume (ou numa pasta mapeada) desaparece quando o container é recriado. Por isso as etapas 17 e 20 (dados e backup) são tão importantes.

Dois comandos aparecem em todo o guia: docker (trabalha com um container ou imagem por vez) e docker compose (trabalha com o projeto inteiro descrito no compose.yml). Em projetos reais, você usa quase só o segundo.

Compose v1 e v2: existe um programa antigo chamado docker-compose (com hífen). Não use. Neste guia o Compose é um plugin do Docker e o comando é docker compose (com espaço). Tutoriais antigos na internet usam o formato com hífen e um campo version: no arquivo; o campo não é mais necessário.

4. Preparar o Ubuntu Server

Executar em: a VM

4.1 Atualizar o sistema e instalar ferramentas básicas

sudo apt update
sudo apt full-upgrade -y
sudo apt install -y ca-certificates curl gnupg jq htop nano bash-completion

O sudo executa o comando como administrador e pede a sua senha. O apt update atualiza a lista de pacotes e o full-upgrade instala as atualizações. O bash-completion faz a tecla Tab completar comandos do Docker, o que poupa muita digitação.

4.2 Fuso horário e relógio

sudo timedatectl set-timezone America/Sao_Paulo
timedatectl status

Resultado esperado: Time zone: America/Sao_Paulo e System clock synchronized: yes. Relógio certo é essencial para logs e para os agendamentos do n8n.

4.3 Conferir IP, espaço em disco e memória

ip -br address
df -h /
free -h

As imagens e os volumes do Docker ficam em /var/lib/docker, dentro do disco principal. Para estudar com n8n e PostgreSQL, 2 CPUs, 4 GB de memória e 30 GB de disco são um ponto de partida confortável. Se o df mostrar bem menos espaço que o disco criado, expanda o volume LVM conforme a etapa 5.5 do guia “Montagem dos servidores Ubuntu”.

Se a VM roda no Proxmox, instale também o agente: sudo apt install -y qemu-guest-agent (e marque a opção QEMU Guest Agent na VM). Se o SSH ainda aceita senha ou o firewall UFW ainda não está configurado, volte às etapas 7, 8 e 14 do guia de montagem dos servidores.

5. Remover pacotes Docker conflitantes

Executar em: a VM

O Ubuntu tem pacotes Docker próprios (docker.io, docker-compose e outros) que conflitam com os pacotes oficiais da Docker. Em uma instalação nova eles normalmente nem existem, mas a limpeza é rápida e evita problemas difíceis de diagnosticar:

sudo apt remove $(dpkg --get-selections docker.io docker-compose docker-compose-v2 docker-doc docker-buildx podman-docker containerd runc | cut -f1)
snap list 2>/dev/null | grep -i docker || echo "Nenhum Docker instalado via snap"

O apt pode informar que nenhum desses pacotes está instalado: isso é o esperado. Se o segundo comando mostrar um Docker instalado via snap, remova com sudo snap remove docker.

Validação: docker --version deve responder command not found neste momento.

6. Instalar o Docker Engine pelo repositório oficial

Executar em: a VM

O repositório oficial da Docker entrega as versões novas e as atualizações pelo próprio apt. Ele tem pacotes para o Ubuntu 26.04 (codinome resolute). Primeiro, a chave de assinatura dos pacotes:

sudo apt update
sudo apt install -y ca-certificates curl
sudo install -m 0755 -d /etc/apt/keyrings
sudo curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
sudo chmod a+r /etc/apt/keyrings/docker.asc

Depois, o cadastro do repositório. O comando descobre sozinho o codinome do seu Ubuntu:

sudo tee /etc/apt/sources.list.d/docker.sources <<EOF
Types: deb
URIs: https://download.docker.com/linux/ubuntu
Suites: $(. /etc/os-release && echo "${UBUNTU_CODENAME:-$VERSION_CODENAME}")
Components: stable
Architectures: $(dpkg --print-architecture)
Signed-By: /etc/apt/keyrings/docker.asc
EOF

sudo apt update
cat /etc/apt/sources.list.d/docker.sources

Confira no arquivo exibido: a linha Suites: deve mostrar resolute, e o sudo apt update deve listar download.docker.com entre as fontes consultadas.

Instale o Docker Engine e os plugins:

sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
PacotePara que serve
docker-ceO Docker Engine, que cria e executa os containers.
docker-ce-cliO comando docker que você digita no terminal.
containerd.ioComponente de baixo nível usado pelo Engine.
docker-buildx-pluginConstrução de imagens (usado quando você criar imagens próprias).
docker-compose-pluginO comando docker compose.
Não use o “script de conveniência” (get.docker.com) que aparece em muitos tutoriais. A própria Docker o recomenda só para testes e desenvolvimento, não para produção. O método do repositório permite atualizar e controlar versões com o apt.

7. Validar a instalação

Executar em: a VM

sudo systemctl status docker --no-pager
sudo systemctl is-enabled docker
docker --version
docker compose version
sudo docker run --rm hello-world

Resultados esperados:

  • o status do serviço mostra active (running) e o is-enabled responde enabled (o Docker sobe sozinho quando a VM liga);
  • docker --version e docker compose version mostram as versões instaladas;
  • o hello-world baixa uma imagem minúscula, executa e imprime uma mensagem começando com Hello from Docker!.

Se o serviço não estiver rodando, inicie com sudo systemctl start docker e consulte a etapa 25.

O parâmetro --rm do último comando apaga o container assim que ele termina. Sem ele, cada teste deixaria um container parado para trás.

8. Usar o Docker sem sudo

Executar em: a VM, na conta de cada pessoa da equipe

Por padrão, só o root fala com o Docker. Para evitar digitar sudo o tempo todo, adicione seu usuário ao grupo docker:

sudo usermod -aG docker $USER
newgrp docker
id | grep docker
docker run --rm hello-world

O newgrp docker ativa o grupo na sessão atual. Em outras janelas, saia do SSH e entre de novo. O comando id deve listar docker, e o hello-world agora funciona sem sudo.

Quem está no grupo docker tem poderes de root na VM. Qualquer pessoa desse grupo consegue montar o disco inteiro dentro de um container. Adicione somente administradores de confiança, e nunca contas de aplicações ou de usuários comuns.

9. Ajustes iniciais: rotação de logs e início automático

Executar em: a VM

Por padrão, o Docker guarda os logs de cada container sem limite de tamanho. Em um servidor que roda por meses, isso pode encher o disco. Configure a rotação antes de criar os containers do projeto:

sudo nano /etc/docker/daemon.json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}

Cada container passa a guardar no máximo 3 arquivos de 10 MB de log. Valide o formato do arquivo e reinicie o Docker:

sudo jq . /etc/docker/daemon.json
sudo systemctl restart docker
docker info --format '{{.LoggingDriver}}'
docker compose version

O jq deve repetir o conteúdo formatado (se mostrar erro, falta uma vírgula ou chave). O docker info deve responder json-file.

Atenção: a nova configuração vale apenas para containers criados depois dela. Containers que já existiam precisam ser recriados (docker compose up -d --force-recreate). Reiniciar o serviço Docker também reinicia os containers em execução, então faça isso fora do horário de uso.

10. Primeiros comandos: imagens e containers

Executar em: a VM

Vamos rodar um servidor web de teste, olhar o que ele faz e depois apagá-lo. Execute linha por linha:

docker run -d --name teste-nginx -p 8081:80 nginx:stable
docker ps
curl -I http://localhost:8081
docker logs teste-nginx
docker exec -it teste-nginx sh
# dentro do container: ls /usr/share/nginx/html ; depois digite: exit
docker stop teste-nginx
docker ps -a
docker rm teste-nginx
docker images
Parte do comandoSignificado
-ddetached: roda em segundo plano e devolve o terminal para você.
--name teste-nginxDá um nome ao container (sem isso o Docker inventa um).
-p 8081:80Publica a porta: porta 8081 da VM → porta 80 do container. Formato sempre VM:container.
nginx:stableA imagem e a etiqueta (tag) da versão. Se você não informar a tag, o Docker usa latest.
docker exec -it … shAbre um terminal dentro do container em execução. Para sair: exit.

Resultados esperados: o docker ps lista o teste-nginx com Up no status; o curl retorna HTTP/1.1 200 OK; depois do docker stop, o container só aparece com docker ps -a (que mostra também os parados); depois do docker rm, ele some. A imagem nginx:stable continua baixada (aparece no docker images), então um novo docker run é instantâneo.

Você pode abrir http://<IP_DA_VM>:8081 no navegador de outro computador enquanto o container estiver no ar. A página padrão do Nginx deve aparecer. Se não abrir, o motivo costuma ser o firewall da rede; veja a etapa 17.

12. Seu primeiro arquivo Compose

Executar em: a VM

Com o docker run, cada opção precisa ser digitada de novo toda vez. O Compose guarda tudo num arquivo, que serve também como documentação do que roda no servidor. Vamos criar um laboratório simples numa pasta de teste:

mkdir -p ~/lab-compose/site
cd ~/lab-compose
echo '<h1>Ola, Compose!</h1>' > site/index.html
nano compose.yml
name: lab

services:
  web:
    image: nginx:stable
    restart: unless-stopped
    ports:
      - "8082:80"
    volumes:
      - ./site:/usr/share/nginx/html:ro
docker compose up -d
docker compose ps
curl http://localhost:8082
docker compose logs --tail 20 web
docker compose down

O curl deve responder <h1>Ola, Compose!</h1>. O docker compose down remove o container e a rede do projeto, mas não apaga a pasta site, que é uma pasta da VM mapeada para dentro do container.

Anatomia do arquivo

CampoSignificado
nameNome do projeto. Prefixa os nomes de containers, redes e volumes (lab-web-1).
servicesLista dos containers do projeto. Cada nome (web) é também o nome DNS na rede interna.
imageQual imagem e tag usar.
restart: unless-stoppedReinicia o container se ele cair e quando a VM ligar, a não ser que você o tenha parado de propósito.
portsPublica portas no formato "VM:container".
volumesLiga uma pasta ou volume ao interior do container. :ro significa somente leitura.
environmentVariáveis de ambiente (configurações) passadas ao container. Você usará na etapa 15.
depends_onDefine a ordem: um serviço só inicia depois que outro estiver pronto.
Volume nomeado ou pasta mapeada? Neste laboratório usamos uma pasta mapeada (./site), boa para arquivos que você edita. Na etapa 15 usaremos volumes nomeados (data:/home/node/.n8n), melhores para dados de aplicações, porque o Docker cuida de local e permissões.

14. Montar o projeto n8n: pasta e arquivo .env

Executar em: a VM

Cada projeto fica em sua própria pasta dentro de /opt/stacks. Assim, qualquer pessoa da equipe sabe onde procurar.

sudo mkdir -p /opt/stacks/n8n /opt/stacks/dozzle
sudo chown -R $USER:$USER /opt/stacks
cd /opt/stacks/n8n

14.1 Por que usar um arquivo .env

O .env guarda senhas, chaves e configurações que mudam entre o laboratório e a produção. O compose.yml só referencia os nomes (${POSTGRES_PASSWORD}). Resultado: o compose.yml pode ser compartilhado e versionado, e os segredos ficam só na VM.

14.2 Criar o .env com segredos gerados automaticamente

O bloco abaixo gera as senhas aleatórias e descobre o IP da VM sozinho. Copie e cole tudo de uma vez:

cd /opt/stacks/n8n
IP=$(ip -4 route get 1.1.1.1 | grep -oP 'src \K\S+')
install -m 600 /dev/null .env
cat >> .env <<EOF
# Versão do n8n (confirme a estável atual em github.com/n8n-io/n8n/releases)
N8N_VERSION=2.41.7

# Fuso horário
TZ=America/Sao_Paulo

# PostgreSQL
POSTGRES_USER=n8n
POSTGRES_PASSWORD=$(openssl rand -hex 24)
POSTGRES_DB=n8n

# Chave que criptografa as credenciais salvas no n8n. NUNCA perca nem troque.
N8N_ENCRYPTION_KEY=$(openssl rand -hex 32)

# Endereço de acesso (laboratório: HTTP pelo IP da VM)
N8N_BIND=0.0.0.0
N8N_HOST=${IP}
N8N_PROTOCOL=http
WEBHOOK_URL=http://${IP}:5678/
N8N_SECURE_COOKIE=false
N8N_PROXY_HOPS=0
EOF
ls -l .env
grep -E '^(N8N_HOST|WEBHOOK_URL)=' .env

Resultados esperados: o ls -l mostra -rw------- (somente você lê o arquivo) e o grep mostra o IP da VM nas duas linhas. Se o IP aparecer vazio, edite o arquivo com nano .env e preencha à mão.

VariávelPara que serve
N8N_VERSIONVersão fixa do n8n. Fixar a versão evita atualização surpresa ao rodar docker compose pull.
N8N_ENCRYPTION_KEYCriptografa as credenciais (senhas e tokens de integrações) guardadas no banco. Sem a mesma chave, um backup restaurado não consegue ler as credenciais.
N8N_BINDEm quais endereços da VM a porta 5678 é publicada. 0.0.0.0 = qualquer um (laboratório). Em produção será 127.0.0.1.
WEBHOOK_URLEndereço público que o n8n mostra e registra para webhooks. Deve ser o endereço que quem acessa realmente usa, terminando com barra.
N8N_SECURE_COOKIEExige HTTPS para o login. No laboratório (HTTP) usamos false; em produção volta para true.
N8N_PROXY_HOPSQuantos proxies existem na frente do n8n. Será 1 em produção, com o Nginx.
Guarde agora no cofre de senhas o conteúdo do .env, principalmente N8N_ENCRYPTION_KEY e POSTGRES_PASSWORD. Para exibir: cat /opt/stacks/n8n/.env (faça isso com a tela fora do alcance de outras pessoas). Nunca envie esse arquivo por chat ou e-mail, nem o coloque em repositório Git.

15. Escrever o compose.yml do n8n com PostgreSQL

Executar em: a VM, na pasta /opt/stacks/n8n

O n8n funciona sozinho com um banco SQLite embutido, mas a própria documentação do n8n recomenda PostgreSQL para uso contínuo, e ele facilita o backup. O arquivo abaixo define os dois serviços.

cd /opt/stacks/n8n
nano compose.yml
name: n8n

services:
  postgres:
    image: postgres:18
    restart: unless-stopped
    environment:
      POSTGRES_USER: ${POSTGRES_USER}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD}
      POSTGRES_DB: ${POSTGRES_DB}
      PGDATA: /var/lib/postgresql/data
    volumes:
      - db:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -h localhost -U ${POSTGRES_USER} -d ${POSTGRES_DB}"]
      interval: 5s
      timeout: 5s
      retries: 10

  n8n:
    image: docker.n8n.io/n8nio/n8n:${N8N_VERSION}
    restart: unless-stopped
    depends_on:
      postgres:
        condition: service_healthy
    ports:
      - "${N8N_BIND}:5678:5678"
    environment:
      DB_TYPE: postgresdb
      DB_POSTGRESDB_HOST: postgres
      DB_POSTGRESDB_PORT: "5432"
      DB_POSTGRESDB_DATABASE: ${POSTGRES_DB}
      DB_POSTGRESDB_USER: ${POSTGRES_USER}
      DB_POSTGRESDB_PASSWORD: ${POSTGRES_PASSWORD}
      N8N_ENCRYPTION_KEY: ${N8N_ENCRYPTION_KEY}
      N8N_HOST: ${N8N_HOST}
      N8N_PROTOCOL: ${N8N_PROTOCOL}
      WEBHOOK_URL: ${WEBHOOK_URL}
      N8N_SECURE_COOKIE: ${N8N_SECURE_COOKIE}
      N8N_PROXY_HOPS: ${N8N_PROXY_HOPS}
      GENERIC_TIMEZONE: ${TZ}
      TZ: ${TZ}
      N8N_ENFORCE_SETTINGS_FILE_PERMISSIONS: "true"
    volumes:
      - data:/home/node/.n8n

volumes:
  db:
  data:

O que cada decisão significa

TrechoPor quê
postgres sem portsO banco não é publicado na VM. Só o n8n, que está na mesma rede do projeto, o alcança, usando o nome postgres como endereço (DB_POSTGRESDB_HOST).
healthcheck + depends_on … service_healthyO n8n só inicia depois que o PostgreSQL responde, evitando erros de conexão na partida.
PGDATAMantenha esta linha. O PostgreSQL 18 mudou o local padrão dos dados; sem ela, ele gravaria fora do volume e seu banco começaria vazio a cada recriação do container (aviso da documentação do n8n).
postgres:18 e N8N_VERSIONVersões fixas. Com latest você nunca sabe qual versão está rodando nem o que mudou numa atualização.
Volumes db e dataGuardam o banco e a pasta .n8n do n8n (configurações e arquivos internos). O Docker os cria como n8n_db e n8n_data (nome do projeto + nome do volume).
restart: unless-stoppedOs dois serviços voltam sozinhos após uma queda ou reinício da VM.

Validar o arquivo antes de subir

docker compose config -q && echo "Arquivo válido"

Se aparecer Arquivo válido sem avisos, siga em frente. Se aparecer variable is not set, você não está na pasta /opt/stacks/n8n ou falta uma linha no .env. Se aparecer erro de sintaxe, confira a indentação (somente espaços).

Evite docker compose config sem o -q em tela compartilhada: ele imprime o arquivo com as senhas já substituídas.

17. Volumes, redes e firewall: onde estão seus dados

Executar em: a VM

17.1 Volumes

docker volume ls
docker volume inspect n8n_db --format '{{.Mountpoint}}'
sudo du -sh /var/lib/docker/volumes/n8n_db/_data

O Mountpoint mostra onde o volume fica no disco da VM (dentro de /var/lib/docker/volumes). Você pode olhar o tamanho, mas nunca edite nem copie arquivos do banco ali dentro com o PostgreSQL em execução. Para guardar dados com segurança, use o backup da etapa 20.

17.2 Redes

docker network ls
docker network inspect n8n_default --format '{{range .Containers}}{{.Name}}  {{.IPv4Address}}{{"\n"}}{{end}}'

O Compose criou a rede n8n_default e colocou os dois containers nela. O segundo comando lista cada container com o IP interno. É por essa rede que o n8n encontra o banco pelo nome postgres, sem depender de IP.

17.3 Como as portas ficam expostas

Forma no compose.ymlQuem consegue acessar
Sem ports (como o postgres)Somente os containers do mesmo projeto.
"127.0.0.1:5678:5678"Somente a própria VM. É o formato de produção: um proxy (Nginx) na VM atende o público.
"5678:5678" ou "0.0.0.0:5678:5678"Qualquer computador que alcance a VM pela rede. É o que o laboratório usa.
Armadilha importante: o Docker passa por cima do UFW. Portas publicadas por containers não respeitam as regras do UFW nem do firewalld; o tráfego é liberado pelo Docker antes do UFW ver. Ou seja, mesmo com ufw default deny incoming, a porta 0.0.0.0:5678 continua aberta para a rede. Além disso, o Docker só é compatível com regras de firewall criadas por iptables/ip6tables, não com regras criadas diretamente por nft.

Duas defesas simples: (1) publicar em 127.0.0.1 tudo o que não precisa ser acessado direto de fora; (2) conferir sempre o que está escutando com o comando abaixo.
sudo ss -lntp | grep -E '5678|8080|docker-proxy'

Cada linha com 0.0.0.0: ou *: está aberta para a rede; 127.0.0.1: está restrita à VM. Para regras avançadas (por exemplo, liberar uma porta publicada apenas para a rede interna), consulte a página oficial “Packet filtering and firewalls” indicada nas referências.

19. Monitoramento, nível 2: Dozzle (painel visual leve)

Executar em: a VM, na pasta /opt/stacks/dozzle

O Dozzle é um painel web leve, de código aberto, que roda em um único container. Ele mostra os containers da VM, deixa ler e pesquisar os logs em tempo real no navegador e exibe o consumo deles, sem instalar bancos de dados nem agentes. É ideal para uma equipe que ainda não domina a linha de comando.

19.1 Criar o usuário de acesso

O Dozzle tem login próprio. Vamos criar o arquivo de usuários antes de subir (a senha é pedida de forma interativa e não fica no histórico do terminal):

cd /opt/stacks/dozzle
mkdir -p data
docker run -it --rm amir20/dozzle generate admin --email ti@suaempresa.com.br --name "Administrador" > data/users.yml
chmod 600 data/users.yml
head -4 data/users.yml

Digite a senha quando for solicitada (o cursor pode não mostrar o que você digita). O arquivo resultante contém o usuário admin e a senha em formato de hash (bcrypt), nunca em texto puro. Guarde a senha no cofre.

19.2 Escrever o compose.yml e subir

nano compose.yml
name: dozzle

services:
  dozzle:
    image: amir20/dozzle:latest
    restart: unless-stopped
    ports:
      - "8080:8080"
    environment:
      DOZZLE_AUTH_PROVIDER: simple
      DOZZLE_HOSTNAME: vm-docker
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      - ./data:/data
docker compose config -q && echo "Arquivo válido"
docker compose up -d
docker compose ps
docker compose logs --tail 20 dozzle

Nos logs deve aparecer que o Dozzle leu o arquivo users.yml. Abra http://<IP_DA_VM>:8080 no navegador e entre com o usuário admin.

19.3 Como usar

  • A lista à esquerda mostra todos os containers da VM, inclusive o próprio Dozzle. Clique em um (por exemplo, n8n-n8n-1) para ver os logs em tempo real.
  • Use a caixa de busca para filtrar por palavras como error ou pelo nome de um workflow.
  • Containers parados ou reiniciando aparecem destacados: é o primeiro lugar para olhar quando alguém avisa que “o n8n parou”.
  • O painel também mostra o consumo de CPU e memória de cada container.
Segurança do Dozzle: para ler containers, ele acessa o docker.sock, que na prática equivale a acesso de root à VM. Por isso: (1) mantenha o login ligado (DOZZLE_AUTH_PROVIDER: simple); (2) mantenha desligadas as opções de ações (parar/iniciar containers) e shell, que ficam desativadas por padrão; (3) nunca exponha a porta 8080 diretamente na internet; (4) em produção, publique só em 127.0.0.1 (etapa 23). Atenção: marcar o socket como somente leitura (:ro) não restringe o que o Dozzle pode fazer, pois as chamadas à API continuam passando; só um “socket proxy” restringe de verdade.
Se, no futuro, a equipe quiser gerenciar containers pela interface (criar, parar, editar stacks), existem painéis mais completos, como o Portainer. Eles são mais pesados e exigem os mesmos cuidados com o docker.sock. Para monitorar e ler logs, o Dozzle é suficiente e bem mais simples.

20. Backup e restauração

Executar em: a VM

Containers são descartáveis; o que importa são os dados. Para o n8n, o backup precisa de três coisas:

O quêOnde estáComo é copiado
Banco (workflows, credenciais criptografadas, execuções)Volume n8n_db (PostgreSQL)pg_dump, que gera uma cópia consistente mesmo com o banco em uso.
Pasta interna do n8nVolume n8n_dataCompactação do volume.
Configuração e chave de criptografiacompose.yml e .envCompactação dos dois arquivos.
Backup sem a N8N_ENCRYPTION_KEY não serve para as credenciais. Se você restaurar o banco em outra VM com uma chave diferente, o n8n não consegue ler as credenciais salvas (senhas e tokens de integrações), e todas teriam que ser recriadas. Por isso o .env entra no backup e no cofre de senhas.

20.1 Script de backup

sudo nano /usr/local/bin/backup-n8n.sh
#!/usr/bin/env bash
# Backup diário do n8n: banco, volume e configuração
set -euo pipefail

PROJETO="/opt/stacks/n8n"
DESTINO="/var/backups/n8n"
RETENCAO_DIAS=14
DATA=$(date +%F_%H%M)

cd "$PROJETO"
set -a; . ./.env; set +a      # carrega POSTGRES_USER e POSTGRES_DB

install -d -m 700 "$DESTINO"

echo "1/3 Dump do PostgreSQL..."
docker compose exec -T postgres pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc \
  > "${DESTINO}/n8n_db_${DATA}.dump"
[ -s "${DESTINO}/n8n_db_${DATA}.dump" ] || { echo "ERRO: dump vazio"; exit 1; }

echo "2/3 Volume n8n_data..."
docker run --rm -v n8n_data:/dados:ro -v "${DESTINO}":/backup alpine \
  tar czf "/backup/n8n_data_${DATA}.tar.gz" -C /dados .

echo "3/3 Configuração (compose.yml e .env)..."
tar czf "${DESTINO}/config_${DATA}.tar.gz" -C "$PROJETO" compose.yml .env

chmod 600 "${DESTINO}"/*"${DATA}"*

# Apaga cópias mais antigas que a retenção
find "$DESTINO" -type f -mtime +"$RETENCAO_DIAS" -delete

echo "Backup concluído em $(date)"
sudo chmod 750 /usr/local/bin/backup-n8n.sh
sudo /usr/local/bin/backup-n8n.sh
sudo ls -lh /var/backups/n8n/

Resultado esperado: três arquivos novos (n8n_db_…dump, n8n_data_…tar.gz e config_…tar.gz), com tamanho maior que zero. Na primeira execução o Docker baixa a imagem alpine, usada só para compactar o volume.

20.2 Agendar com o systemd

O serviço diz o que executar e o timer diz quando:

sudo nano /etc/systemd/system/backup-n8n.service
[Unit]
Description=Backup diário do n8n (banco, volume e configuração)
Requires=docker.service
After=docker.service

[Service]
Type=oneshot
ExecStart=/usr/local/bin/backup-n8n.sh
sudo nano /etc/systemd/system/backup-n8n.timer
[Unit]
Description=Agenda o backup diário do n8n

[Timer]
OnCalendar=*-*-* 02:00:00
Persistent=true

[Install]
WantedBy=timers.target
sudo systemctl daemon-reload
sudo systemctl enable --now backup-n8n.timer
systemctl list-timers backup-n8n.timer
sudo systemctl start backup-n8n.service
sudo journalctl -u backup-n8n.service -n 20 --no-pager

O Persistent=true faz o backup rodar assim que a VM ligar caso ela estivesse desligada no horário agendado.

Backup na mesma VM não protege contra perda da VM. Copie a pasta /var/backups/n8n para fora da VM (outro servidor, NAS ou o backup de VMs do seu hipervisor, agendado depois das 02:00). Como os arquivos contêm segredos, o destino também precisa ser restrito.

20.3 Testar a restauração (sem tocar nos dados reais)

Um backup só vale se a restauração funciona. Este teste restaura o último dump em um banco temporário e o apaga em seguida:

cd /opt/stacks/n8n
ARQUIVO=$(sudo ls -t /var/backups/n8n/n8n_db_*.dump | head -1)
echo "Testando: $ARQUIVO"
docker compose exec -T postgres createdb -U n8n n8n_teste
sudo cat "$ARQUIVO" | docker compose exec -T postgres pg_restore -U n8n -d n8n_teste --no-owner
docker compose exec -T postgres psql -U n8n -d n8n_teste -c "\dt" | head -15
docker compose exec -T postgres dropdb -U n8n n8n_teste

O \dt deve listar as tabelas do n8n (como workflow_entity e credentials_entity). Se listar, o backup está íntegro.

20.4 Restauração real (recuperação de desastre)

Este procedimento substitui o banco atual. Use somente em caso de perda de dados, com o .env original (mesma N8N_ENCRYPTION_KEY) já no lugar.
cd /opt/stacks/n8n
ARQUIVO=$(sudo ls -t /var/backups/n8n/n8n_db_*.dump | head -1)
docker compose stop n8n
docker compose exec -T postgres dropdb -U n8n n8n
docker compose exec -T postgres createdb -U n8n n8n
sudo cat "$ARQUIVO" | docker compose exec -T postgres pg_restore -U n8n -d n8n --no-owner
docker compose start n8n
docker compose logs --tail 30 n8n

Para uma VM nova: instale o Docker (etapas 4 a 9), recrie /opt/stacks/n8n com o compose.yml e o .env do backup, suba apenas o banco (docker compose up -d postgres), restaure como acima e então suba o restante (docker compose up -d).

21. Atualizar imagens com segurança

Executar em: a VM

Como as versões estão fixas, nada muda sozinho. Atualizar é uma decisão sua, em seis passos curtos:

21.1 Atualizar o n8n

  1. Faça um backup agora: sudo systemctl start backup-n8n.service
  2. Leia as notas da versão nova em github.com/n8n-io/n8n/releases, procurando mudanças que quebram compatibilidade (breaking changes).
  3. Troque o número em N8N_VERSION: nano /opt/stacks/n8n/.env
  4. Baixe e aplique:
cd /opt/stacks/n8n
docker compose pull n8n
docker compose up -d
docker compose logs --tail 50 n8n
curl -sf http://localhost:5678/healthz; echo
docker compose ps

O n8n migra sozinho a estrutura do banco ao iniciar uma versão nova; pode demorar um pouco. Teste no navegador se os workflows continuam abrindo e se uma execução manual funciona.

Voltar atrás nem sempre é só trocar o número. Se a versão nova já migrou o banco, a versão antiga pode não conseguir abri-lo. O caminho seguro de reversão é: voltar o N8N_VERSION antigo no .env e restaurar o backup feito no passo 1 (etapa 20.4). Segundo a documentação do n8n, a versão 3.0 está prevista para outubro de 2026: leia com atenção as notas antes de sair da série 2.x e teste primeiro em uma VM de laboratório.

21.2 Atualizar o PostgreSQL

Dentro da mesma versão principal (postgres:18), as correções saem automaticamente: docker compose pull postgres && docker compose up -d. Nunca mude o número principal (de 18 para 19, por exemplo) apenas trocando a tag: o PostgreSQL não abre dados de uma versão principal anterior e o container não sobe (database files are incompatible with server). Esse salto exige backup, criação de um banco novo na versão nova e restauração (consulte o guia oficial de atualização do PostgreSQL).

21.3 Atualizar o Dozzle

cd /opt/stacks/dozzle
docker compose pull
docker compose up -d

Em produção, troque latest por uma versão específica (veja as Releases do projeto) e atualize com o mesmo procedimento do n8n.

21.4 Atualizar o próprio Docker e o Ubuntu

sudo apt update
apt list --upgradable 2>/dev/null | grep -i -E "docker|containerd"
sudo apt upgrade -y
docker compose ps

As atualizações automáticas de segurança do Ubuntu (unattended-upgrades) não cobrem o repositório da Docker: ele precisa ser atualizado manualmente, por exemplo uma vez por mês. Quando o Docker atualiza, os containers reiniciam; faça fora do horário de uso e confirme depois com docker compose ps.

22. Limpeza de espaço (prune)

Executar em: a VM

Com o tempo, versões antigas de imagens acumulam no disco. Veja quanto espaço o Docker usa e limpe só o que é seguro:

docker system df
docker image prune          # remove só imagens "soltas" (sem tag e sem uso)
docker image prune -a       # remove imagens que nenhum container usa (peça confirmação)
docker builder prune        # cache de construção de imagens
docker system df

Depois de uma atualização do n8n, o docker image prune -a libera o espaço da versão antiga. O custo é baixar a imagem de novo se você precisar voltar atrás.

Nunca rode docker volume prune nem docker system prune --volumes com algum projeto parado. Um volume é considerado “sem uso” quando nenhum container o usa, e isso inclui o volume do banco de dados de um projeto que está desligado naquele momento. O resultado é perda definitiva dos dados. Para limpar imagens e containers, os comandos acima bastam.

23. Do estudo à produção

Executar em: a VM e no painel de DNS

O laboratório funciona, mas é acessado por HTTP, com portas abertas para a rede. Esta etapa leva o mesmo ambiente à produção. A tabela resume o que muda; os passos seguintes mostram como.

23.1 Criar o registro DNS e instalar o Nginx

No painel de DNS do domínio, crie um registro A chamado n8n apontando para o IP público da empresa e, no roteador, encaminhe as portas 80 e 443 para esta VM. As etapas 21 e 22 do guia “Montagem dos servidores Ubuntu” explicam DNS, redirecionamento de portas e Certbot em detalhe. Na VM:

sudo apt install -y nginx
sudo ufw allow 80/tcp comment 'HTTP'
sudo ufw allow 443/tcp comment 'HTTPS'
sudo ufw status verbose

Se o UFW ainda não está ativo, configure-o antes (SSH liberado só para a rede interna), conforme a etapa 14 do guia de montagem. Se o servidor Nginx já existe nesta VM por causa de outras aplicações, apenas acrescente o site novo.

23.2 Site do n8n no Nginx

O n8n usa WebSocket para atualizar a tela de execução, então o proxy precisa repassar os cabeçalhos Upgrade. Se o arquivo 00-geral.conf do guia anterior já existe, não repita o bloco map.

sudo nano /etc/nginx/conf.d/00-websocket.conf
map $http_upgrade $connection_upgrade {
    default upgrade;
    ''      close;
}
sudo nano /etc/nginx/sites-available/n8n
server {
    listen 80;
    listen [::]:80;
    server_name n8n.<DOMINIO>;

    access_log /var/log/nginx/n8n.access.log;
    error_log  /var/log/nginx/n8n.error.log;

    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:5678;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade           $http_upgrade;
        proxy_set_header Connection        $connection_upgrade;
        proxy_buffering off;
        proxy_read_timeout 300s;
        proxy_send_timeout 300s;
    }
}
sudo ln -s /etc/nginx/sites-available/n8n /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx

O nginx -t deve terminar com syntax is ok e test is successful. Rode sempre o teste antes do reload.

23.3 Ajustar o n8n para trabalhar atrás do proxy

Edite o .env e troque as linhas abaixo (troque <DOMINIO> pelo seu domínio). O WEBHOOK_URL deve manter a barra no final:

cd /opt/stacks/n8n
nano .env
N8N_BIND=127.0.0.1
N8N_HOST=n8n.<DOMINIO>
N8N_PROTOCOL=https
WEBHOOK_URL=https://n8n.<DOMINIO>/
N8N_SECURE_COOKIE=true
N8N_PROXY_HOPS=1
docker compose up -d
docker compose ps
sudo ss -lntp | grep 5678

O up -d recria o n8n com a nova configuração. Na saída do ss, a porta 5678 deve aparecer em 127.0.0.1:5678 e não em 0.0.0.0.

23.4 Emitir o certificado HTTPS

sudo snap install --classic certbot
sudo ln -sf /snap/bin/certbot /usr/bin/certbot
sudo certbot --nginx -d n8n.<DOMINIO>
sudo certbot renew --dry-run

O Certbot pede um e-mail para avisos de expiração, ajusta o Nginx e configura o redirecionamento de HTTP para HTTPS. O renew --dry-run deve terminar com sucesso, provando que a renovação automática funciona. Abra https://n8n.<DOMINIO>: deve aparecer com cadeado e a tela de login do n8n.

Se o n8n mostrar endereços de webhook com o IP ou localhost, o WEBHOOK_URL não foi aplicado: confira o .env e rode docker compose up -d de novo.

23.5 Fechar o Dozzle para acesso por túnel SSH

Em /opt/stacks/dozzle/compose.yml, mude a linha da porta para publicar só na VM:

    ports:
      - "127.0.0.1:8080:8080"
cd /opt/stacks/dozzle
docker compose up -d

Para abrir o painel, a pessoa da equipe cria um túnel SSH pelo PowerShell do seu computador e acessa http://localhost:8080 no navegador:

ssh -L 8080:127.0.0.1:8080 <SEU_USUARIO>@<IP_DA_VM>

Enquanto a sessão SSH estiver aberta, o painel aparece no seu computador. Ao fechá-la, o acesso termina. Assim o painel não fica disponível na rede.

23.6 Conferir o que está exposto e fixar versões

sudo ss -lntp | grep -E 'docker-proxy|:5678|:8080'
sudo ufw status verbose
docker compose -f /opt/stacks/n8n/compose.yml ps
docker compose -f /opt/stacks/dozzle/compose.yml ps

Nenhuma porta de container deve aparecer com 0.0.0.0. Em seguida, em /opt/stacks/dozzle/compose.yml, troque amir20/dozzle:latest por uma versão específica e anote no cofre quais versões estão em produção.
